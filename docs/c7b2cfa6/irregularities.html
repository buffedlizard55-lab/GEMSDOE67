IR-67-GRID-01mediumTHE ORGANISER'S FOOTPRINT AND THE FEATURE FOOTPRINT DISAGREE. sample_submission.tif is finite on 5,167,373 cells; band 1 of the feature stack is finite on 5,165,852. 3,061 cells are finite in the template but nodata in the features, and 1,540 cells are finite in the features but NaN in the template. A submission that is NaN exactly where the template is NaN therefore fails the shared validator's feature-based 'no NaN inside footprint' check on those 1,540 cells, and a submission that follows the feature footprint fails an exact template match.This lane matches the organiser's own template exactly (verified: nan_pattern_identical_to_sample_submission = true) and reports the validator's feature-based check as a known, explained discrepancy rather than silently choosing the other mask. Both a NaN-outside and an all-finite (0-outside) file are shipped so the owner can submit either; a sibling session reports the same raster scoring identically in both variants (owner-reported, no receipt).

IR-67-PROXY-01highTHE HOLDOUT IS NOT THE EXAM. The hide-and-recover protocol withholds whole catalogue segments and asks the model to recover them; the live exam scores expert-labelled NEW faults that are, by construction, NOT in the catalogue. Sibling sessions measured the rank-correlation of this instrument family with the live board at +0.087 (catalogue-hidden) to +0.51 (drift-corrected), n = 12, p ~ 0.09 - i.e. a screen, not a predictor (inherited measurement, not re-measured here).The holdout result is labelled HOLDOUT-DTI everywhere and is used only to reject an arm that is worse than its own control. The emission design is driven by the published metric's exact first-order condition plus the anatomy meta-analysis of the pinned registry rasters (evidence/e0_meta_analysis.json), which is measured from bytes in this checkout even though its score column is owner-reported.
IR-67-PREVALENCE-01mediumThe calibrated greedy marginal-DTI selector needs the hidden truth's cell count to calibrate q-hat, and that number is unknowable here. The shipped dot count is the low-prevalence arm's, and the high-prevalence arm's count is published beside it so the sensitivity is visible.
IR-67-UNIQ-01mediumThe literal 3-px duplicate rule ('more than 70% of my dots within 3 px of one registry raster's dots -> duplicate, stop') is DEGENERATE for this corpus: several pinned rasters are continuous fields positive on essentially every footprint cell, so any non-empty dot field is within 3 px of ~100% of their dots - including the family's own best-reported raster. Sibling sessions documented the same finding and measured the incumbent at 0.999/0.889/0.772 against three space-filling comparators.Both readings are computed and published side by side: 'literal' over all 62 pinned rasters and 'like_for_like' restricted to rasterised dot families (<=50% of footprint cells positive). The gate uses the like-for-like reading and the literal one is reported as a property of the registry, not of this candidate. Re-measured here, not inherited.

IR-67-DECODE-01lowThe first implementation of the tip-extension arm produced ZERO extension cells, because the along-strike walk was tested against the NMS-thinned propensity field: non-maximum suppression removes exactly the off-ridge cells a tip extension must cross, so the mechanism was unfalsifiable by construction and arm A2 was bit-identical to arm A1.Found by reading the emitted diagnostics (extension_cells = 0, A2 - A1 = 0.0000 in both folds) rather than by assuming the arm worked. Fixed in the shared module (decode67.extend_past_tips now takes an un-thinned walk_support field) and the gate was re-run; both runs are preserved as evidence.
