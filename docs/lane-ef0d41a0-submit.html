How to make a submission, step by step

Written for a reader who has never opened the competition before.

The raster is published because the brief requires a downloadable, format-valid, unique GeoTIFF — it is for inspection, not for a submission slot. The steps below are the general procedure; use them with a file you trust.

The two-minute version

  1. Enrol. Open the competition page, click “Compete!” in the sidebar and accept the rules.
  2. Download your raster. A valid entry is a single-layer float32 GeoTIFF, EPSG:32611 (UTM 11N), 100 m pixels, exactly the same grid as sample_submission.tif, values in [0, 1] with higher meaning “more likely to be a fault”. Pixels outside the footprint must be null/NaN.
  3. Check it locally before you spend a slot. Compare CRS, transform, shape (3730 × 3292), dtype and value range against sample_submission.tif. The single most common rejection is “Predicted values must be in range [0, 1]” — a raster written in 0…255, or with a −9999 nodata sentinel, fails immediately.
  4. Upload. On the competition page click Submit in the sidebar, then “Make new submission”, choose the .tif, add a name and a short description, and confirm. Uploading the .zip is only correct if the platform asks for an archive; when in doubt, upload the .tif.
  5. Read the score, not the rank. The public score is computed against the private expert-labelled test set; the same submission is scored again for the Final Prize Round against an expanded label set built from expert review of all submissions. A week-to-week rank movement of a few places is usually noise.
  6. Keep a record. Store the exact file, its sha256, the score and the date. This lane does that in evidence/; copying the habit saves a lot of confusion later.

Rules that matter for this challenge

  • External data is encouraged but must be licensed for the challenge and shareable with the organizers for independent verification.
  • Training on the provided labels is allowed even though the training and test sets overlap spatially: the organizers state that newly identified faults inside the GeoDAWN region are the test target.
  • One file per submission, single band, float32, values confined to [0, 1].
  • Deadline: Dec 3, 2026, 11:59 p.m. UTC.
